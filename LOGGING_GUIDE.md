# Logging Guide

## Log Levels

| Level | Value | When to expect |
|-------|-------|----------------|
| `fatal` | 60 | Unrecoverable errors (not currently emitted) |
| `error` | 50 | Unhandled exceptions, chunk generation failure, job failure |
| `warn` | 40 | AppError responses (4xx/5xx), validation errors, subtitle timing warnings, TTS retries |
| `info` | 30 | Request start/completion, job lifecycle (created/started/completed), export complete, segment generation |
| `debug` | 20 | Job cleanup, detailed internal state (set `LOG_LEVEL=debug`) |
| `trace` | 10 | (not currently used) |

Configure with `LOG_LEVEL` env var. Default: `info` (production) / `debug` (development).

## Log Format

### Production (default)
Each log line is a newline-delimited JSON object:
```json
{"level":30,"time":1712345678901,"pid":1234,"hostname":"myhost","req":{"id":"<uuid>","method":"POST","url":"/api/generate"},"msg":"request completed"}
```

### Development (`NODE_ENV=development`)
Pretty-printed with colorized output via `pino-pretty`:
```
[10:23:45] INFO: request completed
    reqId: "abc-123"
    method: "POST"
    url: "/api/generate"
    statusCode: 200
```

## Request ID

Every HTTP request receives a **unique request ID** (UUID v4) generated by the `requestLogger` middleware.

### Access in code
```ts
// In controllers/middleware:
req.id                  // string — the request ID
req.log                 // Pino logger instance scoped to this request
req.log.info('message') // Automatically includes req.id
```

### In error handler
The error handler logs the `requestId` with every error:
```json
{"level":50,"requestId":"abc-123","err":{...},"msg":"Unhandled error"}
```

### In responses
The request ID is **not** included in the JSON response body. It is only present in log output. You can add it to error responses by modifying the error handler if needed.

## Correlation Strategy

1. **Request ID** — every HTTP request gets a UUID. All log entries during that request include `req.id` (via pino-http).
2. **Job ID** — TTS jobs and subtitle jobs each have a UUID. All lifecycle logs include `jobId` or `subtitleJobId`.
3. **Chunk context** — TTS chunk generation logs include `chunkNum` and `totalChunks`.
4. **Error correlation** — errors include both `requestId` (HTTP context) and `jobId` (job context).

This enables tracing a request through the system:
```
Client → HTTP request (req.id)
       → Job created (jobId + req.id)
       → Chunks generated (chunkNum, jobId)
       → Job completed/failed (jobId)
```

## Example Logs

### Request completed (production JSON)
```json
{"level":30,"time":1712345678901,"pid":1234,"hostname":"myhost","req":{"id":"a1b2c3d4","method":"POST","url":"/api/generate","headers":{"content-type":"application/json"}},"res":{"statusCode":200,"headers":{"content-type":"audio/mpeg"}},"responseTime":4523,"msg":"request completed"}
```

### AppError (warn)
```json
{"level":40,"time":1712345678902,"pid":1234,"hostname":"myhost","requestId":"a1b2c3d4","err":{"type":"AppError","message":"Job not found","stack":"..."},"code":"JOB_NOT_FOUND","statusCode":404,"msg":"Job not found"}
```

### Unhandled error (error)
```json
{"level":50,"time":1712345678903,"pid":1234,"hostname":"myhost","requestId":"a1b2c3d4","err":{"type":"Error","message":"Something broke","stack":"..."},"msg":"Unhandled error"}
```

### Job lifecycle
```json
{"level":30,"time":1712345678904,"pid":1234,"hostname":"myhost","jobId":"job-uuid-123","voice":"km-KH-PisethNeural","textLength":500,"msg":"Job started"}
{"level":30,"time":1712345678905,"pid":1234,"hostname":"myhost","jobId":"job-uuid-123","fromStatus":"processing","toStatus":"completed","msg":"Job status: processing → completed"}
```

### Chunk generation
```json
{"level":30,"time":1712345678906,"pid":1234,"hostname":"myhost","chunkNum":3,"totalChunks":10,"msg":"Chunk 3/10 done"}
{"level":40,"time":1712345678907,"pid":1234,"hostname":"myhost","chunkNum":"chunk-003.mp3","attempt":2,"delay":4000,"msg":"Retry 2/3 in 4000ms..."}
```

### Subtitle lifecycle
```json
{"level":30,"time":1712345678908,"pid":1234,"hostname":"myhost","subtitleJobId":"sub-job-456","segmentCount":20,"msg":"Subtitle job created"}
{"level":30,"time":1712345678909,"pid":1234,"hostname":"myhost","subtitleJobId":"sub-job-456","completedCount":18,"failedCount":2,"totalCount":20,"status":"failed","msg":"Subtitle segment generation finished"}
{"level":30,"time":1712345678910,"pid":1234,"hostname":"myhost","subtitleJobId":"sub-job-456","filename":"subtitles-abc123.mp3","size":2048576,"msg":"Subtitle export completed"}
```

### Subtitle SRT warning
```json
{"level":40,"time":1712345678911,"pid":1234,"hostname":"myhost","startTime":5000,"endTime":2000,"msg":"Invalid subtitle timing: end 2000ms <= start 5000ms, skipping block"}
```

### Export complete
```json
{"level":30,"time":1712345678912,"pid":1234,"hostname":"myhost","completedCount":20,"gapCount":3,"durationMs":120000,"msg":"Export complete: 20 segments, 3 gaps, duration=120000ms"}
```

### CLI (pretty-printed)
Not JSON — `pino-pretty` renders human-readable output for CLI scripts:
```
[10:23:45] INFO: Fetching Khmer voices...
[10:23:46] INFO: Input text: 1000 characters
[10:23:46] INFO: Using voice: km-KH-PisethNeural
[10:23:47] INFO: Chunk 1/5 done
[10:23:48] INFO: Chunk 2/5 done
[10:23:50] INFO: Done! Audio saved to: C:\output\output.mp3 (2.5s)
```

### Debug (cleanup jobs)
```json
{"level":20,"time":1712345678913,"pid":1234,"hostname":"myhost","jobId":"old-job-uuid","msg":"Job cleaned up"}
```
